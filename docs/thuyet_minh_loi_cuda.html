1.1. Tổng quan hệ thống

Bài toán. Với mỗi câu hỏi y khoa tiếng Việt, trả về danh sách tài liệu liên quan (doc_id trong danh sách 1.220.598 URL của BTC: Việt, Trung, PubMed tiếng Anh) và một đoạn nội dung trích nguyên văn cho mỗi tài liệu. Đánh giá bằng F2 cấp tài liệu và F2 cấp đoạn.

Phương pháp. Hệ thống truy hồi lai hai tầng, chạy hoàn toàn trên một máy (GPU 16 GB):

  1. Truy hồi tầng một — chín lượt tìm riêng theo từng nhóm ngôn ngữ (xác định theo website): BM25 theo âm tiết và theo cặp âm tiết liền nhau cho tiếng Việt, BM25 tách từ jieba cho tiếng Trung, BM25 cho tiếng Anh, và năm lượt dense BGE-M3 (câu Việt → tài liệu Việt / Trung / Anh; câu dịch Trung → tài liệu Trung; câu dịch Anh → tài liệu Anh).
  2. Gộp thứ hạng — Reciprocal Rank Fusion có trọng số trong từng nhóm, k = 150; giữ 300 ứng viên Việt và 130 ứng viên Trung mỗi câu (nhóm Anh có hạn mức 0: bài nộp thử chỉ gồm tài liệu PubMed đạt 0 điểm).
  3. Xếp hạng lại — Qwen3-Reranker chấm 150 ứng viên Việt và 50 ứng viên Trung đầu tiên; đầu vào là câu hỏi đầy đủ cùng tiêu đề và đoạn khớp nhất của tài liệu; điểm là xác suất token “yes”. Bài nộp cuối dùng trung bình điểm của bản 4B và 8B.
  4. Chọn kết quả đầu ra — số tài liệu thay đổi theo từng câu: giữ tài liệu có điểm ≥ τ·(điểm cao nhất của câu đó), τ được dò để trung bình 140 tài liệu/câu (75% Việt); mỗi tài liệu kèm một đoạn 4.000 ký tự (Trung: 2.000) quanh vị trí khớp nhất.

Hình 1. Luồng xử lý từ câu hỏi đầu vào đến danh sách tài liệu và đoạn nội dung.

Cấu hình và prompt. Dịch câu hỏi: nhiệt độ 0, tắt chế độ suy nghĩ, đầu ra ràng buộc JSON schema {"zh", "en"}; system prompt:

You are a professional medical translator. Translate the Vietnamese medical question into: 1. zh: Simplified Chinese, phrased naturally like a patient asking on a Chinese medical Q&A website, using standard Chinese medical terms. 2. en: English, using standard medical terminology as used in PubMed articles. Keep every number, unit, lab value, drug name and abbreviation exactly as written. Translate faithfully: keep all details, add nothing, and do not answer the question.

Xếp hạng lại (định dạng chuẩn của Qwen3-Reranker; điểm = P(“yes”) / (P(“yes”) + P(“no”)) ở token cuối):

<|im_start|>system
Judge whether the Document meets the requirements based on the Query and the Instruct provided. Note that the answer can only be "yes" or "no".<|im_end|>
<|im_start|>user
<Instruct>: Given a Vietnamese patient's medical question, judge whether the document is relevant to it
<Query>: {câu hỏi}
<Document>: {tiêu đề}
{đoạn khớp nhất ≤ 1.200 ký tự}<|im_end|>
<|im_start|>assistant
<think>

</think>

Chỉ dùng khi phát triển (không nằm trong quy trình tạo bài nộp): Qwen3-14B và Gemma 3 12B (Ollama) làm giám khảo cho một tập phát triển tự gán nhãn trên 300 câu (llm_judge.py), dùng để so sánh các phương án xếp hạng lại.

1.5. Hướng dẫn cài đặt và chạy lại

Chi tiết đầy đủ trong README.md của repo. Tóm tắt:

git clone https://github.com/sonIT2005/R2AI-retrieval-of-medical-documents.git vibiomir && cd vibiomir
pip install -r requirements-clean.txt                          # conda base, Python 3.14
conda create -n vibiomir python=3.11 -y && conda activate vibiomir
pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements-search.txt && ollama pull qwen3:8b
# dữ liệu: hf download (mục 1.2) + tar -xf vibiomir_db_extra.tar
python clean_corpus.py                                         # ~1 giờ 20 (conda base)
python embed_corpus.py                                         # ~3 giờ GPU
python search_docs.py --quota 300,130,0 --rrf-k 150 --out D_bi02   # ~20 phút
./build_submission.sh prr_m140                                 # Qwen3-Reranker-4B → bài 0,3606
RERANK=ens ./build_submission.sh ens_m140                      # gộp 4B + 8B → bài vòng private

Tái tạo nhanh từ dữ liệu tăng tốc (không cần làm sạch, tạo vector, chạy reranker):

CAND=results/D_bi02.jsonl ./build_submission.sh prr_m140
CAND=results/D_bi02.jsonl RERANK=ens ./build_submission.sh ens_m140
